# CSS 09 - 调试性能兼容性与面试避坑

> [!tip] CSS 高手的标志
> 不是记住所有属性，而是能快速定位：样式为什么没生效、布局为什么撑爆、层级为什么盖不上、动画为什么卡、移动端为什么变形。

## DevTools 调试顺序

1. 选中元素，看 Elements 面板。
2. 看 Styles，确认规则是否命中。
3. 看属性有没有被划掉。
4. 看 Computed，确认最终计算值。
5. 看 Layout，检查盒模型尺寸。
6. 看父元素的 display、overflow、position。
7. 看是否存在媒体查询覆盖。
8. 看是否有伪类状态，如 hover、focus。

> [!success] 最快排查口诀
> 先看有没有命中，再看有没有被覆盖，再看最终计算值，最后看父级布局限制。

## 调试面板关键字认知

### Elements

浏览器 DevTools 里查看 DOM 结构的地方。你可以看到元素、class、属性，以及它对应的 CSS 规则。

### Styles

显示当前元素命中的 CSS 规则。被划掉的声明表示被覆盖或无效。

### Computed

显示浏览器最终计算出来的样式。排查“到底最后是多少”时看这里。

### Box model

盒模型可视化区域。能直接看到 content、padding、border、margin 各是多少。

### Network

网络面板。CSS 文件没加载、路径 404、缓存异常，可以从这里查。

### Performance

性能面板。动画卡顿、重排重绘、长任务，可以从这里分析。

## 样式不生效常见原因

| 症状 | 常见原因 |
|---|---|
| CSS 文件完全没效果 | 路径错误、文件未加载、缓存 |
| 某一条属性没效果 | 属性拼错、值非法、被覆盖 |
| 宽高不生效 | 元素是 `inline` |
| `z-index` 没效果 | 没有定位或被层叠上下文限制 |
| `position: absolute` 跑偏 | 父元素没写 `position: relative` |
| `margin` 不符合预期 | 外边距折叠 |
| Flex 子项撑爆 | 缺少 `min-width: 0` |
| sticky 不生效 | 父元素 overflow 限制或没有滚动空间 |

## 溢出问题

常见原因：

1. 固定宽度太大。
2. 长单词、长 URL 不换行。
3. 图片没有 `max-width: 100%`。
4. Flex 子项默认最小宽度撑开。
5. Grid 子项内容最小尺寸撑开。

常用修复：

```css
img {
  max-width: 100%;
  display: block;
}

.content {
  min-width: 0;
}

.text {
  overflow-wrap: anywhere;
}

.grid {
  grid-template-columns: repeat(3, minmax(0, 1fr));
}
```

## 溢出关键字认知

| 关键字 | 作用 |
|---|---|
| `overflow-wrap: anywhere` | 长单词或 URL 也允许换行 |
| `white-space: nowrap` | 强制不换行，常配合单行省略 |
| `text-overflow: ellipsis` | 溢出时显示省略号 |
| `min-width: 0` | 允许 Flex/Grid 子项收缩 |
| `max-width: 100%` | 图片或媒体不超过父容器 |

> [!warning] 横向滚动条通常是信号
> 页面突然出现横向滚动条，优先查固定宽度、长文本、图片、Flex/Grid 子项最小宽度。

## 文本省略

单行省略：

```css
.title {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
```

多行省略：

```css
.desc {
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

> [!warning] 多行省略有兼容性细节
> `-webkit-line-clamp` 在现代浏览器里很常用，但属于带前缀的实现。重要页面要实际测试目标浏览器。

## 居中方案总结

Flex 居中：

```css
.center {
  display: flex;
  align-items: center;
  justify-content: center;
}
```

Grid 居中：

```css
.center {
  display: grid;
  place-items: center;
}
```

绝对定位居中：

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}
```

## 性能基础

浏览器渲染大致包括：

1. Style：计算样式。
2. Layout：计算布局。
3. Paint：绘制。
4. Composite：合成。

更容易触发布局的属性：

1. `width`
2. `height`
3. `top`
4. `left`
5. `margin`
6. `padding`

更适合动画的属性：

1. `transform`
2. `opacity`

> [!danger] 动画卡顿排查
> 如果动画卡，先看是不是在频繁改变宽高、位置、边距。能用 `transform` 替代就不要动 `top/left/width/height`。

## 性能关键字认知

### reflow / layout

重新计算元素的大小和位置。比如改 `width`、`height`、`margin`，可能触发布局。

### repaint

重新绘制像素。比如改 `color`、`background`、`box-shadow`，可能触发重绘。

### composite

合成图层。`transform`、`opacity` 动画通常更容易走合成，相对更稳。

### will-change

提前告诉浏览器某个属性可能会变化。

```css
.card {
  will-change: transform;
}
```

> [!warning] will-change 不要乱加
> 它可能增加内存占用。只在确实有高频动画、并且验证有收益时使用。

## 兼容性处理

1. 查目标用户使用什么浏览器。
2. 用 MDN 或 Can I Use 确认特性支持。
3. 用渐进增强思路：基础功能先可用，新特性再增强。
4. 必要时写 fallback。
5. 在真实设备或浏览器里测试。

示例：

```css
.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}

@supports (display: grid) {
  .cards {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  }
}
```

## 兼容性关键字认知

| 关键词 | 含义 |
|---|---|
| fallback | 兜底方案，新特性不支持时仍可用 |
| progressive enhancement | 渐进增强，先保证基础可用，再用新能力增强 |
| `@supports` | 浏览器支持某特性时才应用样式 |
| prefix | 浏览器前缀，比如 `-webkit-` |

兼容性不是“所有浏览器一模一样”，而是目标用户的浏览器里功能可用、体验可接受。

## 面试高频问题

### 1. 盒模型是什么

盒模型由 content、padding、border、margin 组成。默认标准盒模型里 `width` 只包含 content；设置 `box-sizing: border-box` 后，`width` 包含 content、padding、border。

### 2. CSS 优先级怎么算

先看来源和重要性，再看选择器优先级，再看书写顺序。粗略顺序是：行内样式 > ID > class/属性/伪类 > 标签/伪元素。同优先级后写覆盖先写。

### 3. Flex 和 Grid 区别

Flex 是一维布局，适合一行或一列的空间分配和对齐。Grid 是二维布局，适合同时处理行和列，比如卡片网格、页面骨架。

### 4. BFC 是什么

BFC 是块级格式化上下文，可以看作独立布局区域。常见作用是清除浮动、阻止外边距折叠、避免被浮动覆盖。常见触发方式有 `display: flow-root`、`overflow: hidden`、`display: flex`、`display: grid`。

### 5. 为什么 `z-index` 不生效

可能元素没有定位，也可能它处在新的层叠上下文内部。父元素的 `transform`、`opacity`、`z-index` 等都可能创建层叠上下文。

### 6. 如何做响应式

常见策略是移动优先、弹性布局、媒体查询、图片自适应、容器最大宽度、Grid 的 `auto-fit + minmax`。

### 7. CSS 动画怎么优化

优先动画 `transform` 和 `opacity`，减少影响布局的属性变化。控制动画范围和时长，避免大量元素同时重排。

## 项目避坑清单

> [!danger] 上线前检查
> 1. 页面是否有横向滚动条。
> 2. 长标题、长 URL 是否撑爆。
> 3. 图片是否限制最大宽度。
> 4. 弹窗、下拉、tooltip 层级是否正确。
> 5. 移动端导航是否可用。
> 6. 表单 focus 状态是否明显。
> 7. disabled 状态是否不可点击且可识别。
> 8. hover 效果是否不依赖移动端。
> 9. 主题色、字号、间距是否统一。
> 10. 是否存在大量 `!important`。

> CSS 大神不是不遇到布局问题，而是知道从命中、覆盖、盒模型、父级布局、层叠上下文和浏览器渲染链路一步步查。
