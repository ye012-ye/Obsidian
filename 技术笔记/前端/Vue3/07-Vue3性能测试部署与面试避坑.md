# Vue3 性能、测试、部署与面试避坑

> [!info] 本章抓什么
> 项目能跑只是第一步。真正上线要考虑首屏、包体、路由懒加载、错误处理、测试、构建部署、缓存、线上排查。面试也最喜欢从这些地方追问真实经验。

## 性能优化方向

| 方向 | 具体做法 |
|---|---|
| 减少首屏资源 | 路由懒加载、组件懒加载、按需引入 |
| 减少重复渲染 | 合理拆组件、稳定 key、避免无意义响应式 |
| 减少请求压力 | 缓存、分页、防抖、合并请求 |
| 减少包体 | 分包、按需导入、分析 bundle |
| 提升感知速度 | loading、骨架屏、预加载 |

## 路由懒加载

```js
const routes = [
  {
    path: "/dashboard",
    component: () => import("@/views/DashboardView.vue"),
  },
];
```

这样页面组件会被拆成独立 chunk，访问对应路由时再加载。

## v-memo 与 v-once

`v-once`：只渲染一次。

```vue
<h1 v-once>{{ title }}</h1>
```

`v-memo`：依赖不变时跳过更新。

```vue
<div v-for="item in list" :key="item.id" v-memo="[item.id, item.selected]">
  {{ item.name }}
</div>
```

> [!warning] 不要过早优化
> 先用 Performance、Vue Devtools、真实数据定位瓶颈。没有证据时乱加缓存和 memo，可能让代码更难维护。

## 请求优化

搜索防抖：

```js
import { watch } from "vue";

let timer;

watch(keyword, () => {
  clearTimeout(timer);
  timer = setTimeout(() => {
    page.value = 1;
    loadList();
  }, 300);
});
```

避免重复提交：

```js
async function submit() {
  if (submitting.value) return;

  submitting.value = true;
  try {
    await saveForm();
  } finally {
    submitting.value = false;
  }
}
```

## 测试策略

| 测试类型 | 测什么 |
|---|---|
| 单元测试 | 工具函数、composable、store |
| 组件测试 | 组件渲染、交互、emit |
| E2E 测试 | 登录、下单、核心业务流程 |

Vitest 示例：

```js
import { describe, expect, it } from "vitest";
import { calculateTotal } from "@/utils/order";

describe("calculateTotal", () => {
  it("calculates order total", () => {
    expect(calculateTotal([{ price: 10, count: 2 }])).toBe(20);
  });
});
```

Pinia 测试思路：

1. 创建测试 Pinia。
2. 初始化 store。
3. 调 action。
4. 断言 state 和 getter。

## 构建与部署

```bash
npm run build
npm run preview
```

部署前检查：

> [!success] 上线清单
> - 生产接口地址正确。
> - `npm run build` 通过。
> - `dist` 能被静态服务器访问。
> - 刷新二级路由不 404。
> - 静态资源路径正确。
> - 环境变量没有泄露敏感信息。

> - 错误监控和版本号可追踪。

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

## 线上排查

常见问题：

| 现象 | 排查方向 |
|---|---|
| 白屏 | 控制台错误、资源 404、路由 base、环境变量 |
| 登录后立刻退出 | token 保存、请求头、401 处理、时间过期 |
| 页面刷新 404 | 服务端没有回退到 `index.html` |
| 数据不更新 | 响应式丢失、浅拷贝、错误 key |
| 请求重复 | watch 写法、生命周期重复触发、组件重复挂载 |
| 打包后接口错 | 生产环境变量、代理只在开发环境生效 |

## 面试高频题

### Vue2 和 Vue3 的主要区别

答题模板：

> Vue3 使用 Proxy 作为响应式基础，Composition API 更适合复杂逻辑复用，支持 `<script setup>`，性能和 TypeScript 支持更好，生态上常配合 Vite、Vue Router 4、Pinia。Vue2 的 Options API 仍可理解，但新项目通常优先 Vue3 现代写法。

### ref 和 reactive 区别

答题模板：

> `ref` 可以包裹任意值，JS 中通过 `.value` 访问；`reactive` 主要用于对象，返回 Proxy。基础类型、数组、需要整体替换的数据常用 `ref`，表单对象可用 `reactive`。解构 `reactive` 可能丢失响应式，要用 `toRefs`。

### computed 和 watch 区别

答题模板：

> `computed` 用于根据响应式依赖计算派生值，有缓存，没有副作用；`watch` 用于监听变化后执行副作用，比如请求接口、写缓存、调用外部 API。如果只是从一个状态算另一个状态，优先 `computed`。

### 为什么用 Pinia

答题模板：

> Pinia 是 Vue 官方推荐的状态管理方案之一，API 比 Vuex 更轻，Composition API 风格更自然，TypeScript 推断更好。项目里我会把登录用户、权限、全局配置、跨页面共享数据放进 Pinia，组件局部状态仍保留在组件内。

### Vue 项目权限怎么做

答题模板：

> 常见做法是后端登录返回 token、用户信息和权限码。前端用 Pinia 保存用户状态，Router 守卫判断是否登录和是否有路由权限，菜单根据角色或权限码过滤，按钮用权限指令或 composable 控制。真正的安全仍必须以后端鉴权为准，前端权限主要是体验层控制。

## 避坑清单

> [!danger] Vue3 高频坑
> - `ref` 在 JS 中忘记 `.value`。
> - 解构 `reactive` 或 Pinia store 导致响应式丢失。
> - `watch` 里修改被监听对象，造成循环触发。
> - `v-for` 使用 index 作为 key。
> - 子组件直接修改 props。
> - 请求失败没有错误提示，页面一直 loading。
> - 路由守卫里异步状态没准备好就判断权限。
> - 生产环境刷新二级路由 404。
> - 把所有状态都放 Pinia，导致全局状态混乱。
