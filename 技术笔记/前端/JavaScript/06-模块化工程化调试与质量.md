# JavaScript 模块化、工程化、调试与质量

> [!info] 本章抓什么
> 能写 JS 是入门，能组织 JS 才是工程能力。真实项目需要拆模块、管理依赖、调试问题、统一格式、控制质量。

## ES Modules

导出：

```js
// math.js
export function add(a, b) {
  return a + b;
}

export const PI = 3.14159;
```

导入：

```js
// main.js
import { add, PI } from "./math.js";

console.log(add(1, 2), PI);
```

默认导出：

```js
// request.js
export default async function request(url) {
  const response = await fetch(url);
  return await response.json();
}
```

```js
import request from "./request.js";
```

> [!warning] 命名导出更利于维护
> 默认导出可以任意命名，重构时更容易乱。工具函数、组件库、状态模块优先用命名导出。

## 目录组织

一个简单项目可以这样拆：

```text
src/
  api/
    user.js
  components/
    TodoItem.js
  utils/
    format.js
  state/
    todoStore.js
  main.js
```

拆分原则：

| 模块 | 放什么 |
|---|---|
| `api` | 请求后端接口 |
| `components` | 页面或 UI 单元 |
| `utils` | 无业务状态的纯工具函数 |
| `state` | 共享状态 |
| `main` | 应用入口 |

## npm 基础

```bash
npm init -y
npm install lodash
npm install -D vite eslint prettier
```

| 文件 | 作用 |
|---|---|
| `package.json` | 项目描述、脚本、依赖 |
| `package-lock.json` | 锁定依赖版本 |
| `node_modules` | 实际安装的依赖 |

常用脚本：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

## Vite 基础

Vite 是现代前端常用开发工具，负责开发服务器、模块加载、热更新、生产构建。

```bash
npm create vite@latest my-app -- --template vanilla
cd my-app
npm install
npm run dev
```

Vue3 项目通常使用 `npm create vue@latest`，详见 [[01-快速入门项目结构与SFC]]。

## 调试工具

浏览器 DevTools 常用面板：

| 面板 | 用途 |
|---|---|
| Elements | 看 DOM 和 CSS |
| Console | 看日志和错误 |
| Sources | 打断点调试 |
| Network | 看请求、状态码、响应 |
| Application | 看 storage、cookie、缓存 |
| Performance | 分析性能 |

断点调试：

```js
function calculateTotal(items) {
  debugger;
  return items.reduce((sum, item) => sum + item.price * item.count, 0);
}
```

> [!success] 调试顺序
> 先复现问题，再看控制台错误，然后看 Network，再打断点看变量。不要靠猜。

## 代码质量

格式化解决“长什么样”：

```bash
npm install -D prettier
```

Lint 解决“有没有明显问题”：

```bash
npm install -D eslint
```

测试解决“改完有没有坏”：

```bash
npm install -D vitest
```

简单测试：

```js
import { describe, expect, it } from "vitest";
import { add } from "./math.js";

describe("add", () => {
  it("adds two numbers", () => {
    expect(add(1, 2)).toBe(3);
  });
});
```

## 错误处理与日志

```js
window.addEventListener("error", (event) => {
  console.error("全局错误", event.error);
});

window.addEventListener("unhandledrejection", (event) => {
  console.error("未处理 Promise 错误", event.reason);
});
```

真实项目中，前端错误通常会上报到监控平台，至少要记录：

1. 错误信息。
2. 页面 URL。
3. 用户操作路径。
4. 浏览器信息。
5. 版本号。

## 工程化检查清单

> [!success] 项目交付前至少检查
> - `npm run build` 能通过。
> - 控制台没有明显错误。
> - 接口失败有提示。
> - 表单有校验。
> - 关键页面刷新不丢状态。
> - 列表为空、加载中、失败都有 UI。
> - 代码格式统一。
